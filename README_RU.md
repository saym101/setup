# 🚀 Скрипт настройки и администрирования Debian/Ubuntu

*[Read in English](README.md)*

Интерактивный Bash-скрипт для настройки и администрирования сервера на Debian или Ubuntu — от первичной настройки (hostname, локаль, часовой пояс, hardening SSH, пользователи) до постоянного управления сетью, файрволом и MOTD. Один самодостаточный файл, меню-интерфейс, цветной вывод.

## ✨ Возможности

### 📦 Программное обеспечение
* Два независимо редактируемых набора пакетов — **рекомендуемый** базовый набор и отдельный набор **диагностических утилит** (`ethtool`, `nmap`, `tcpdump`, `net-tools`, `qrencode`) — оба показываются перед установкой и редактируются прямо в строке (добавить/убрать пакет) без правки кода.

### 🌐 Настройка сети
Полноценный раздел настройки сети, который никогда не предполагает `eth0` и не гадает про конфигурацию:
* **Определение backend:** скрипт определяет, чем управляется сеть — **Netplan**, **NetworkManager**, **systemd-networkd** или классический `/etc/network/interfaces`, — и показывает это перед любым изменением.
* Статический IPv4 / переключение на DHCP, gateway, несколько DNS-серверов (добавить/изменить/удалить), IPv6 (SLAAC/DHCPv6/статический/отключение), статические маршруты, MTU, поднятие/отключение интерфейса, перезапуск сетевой службы.
* Полноценная диагностика: `ip addr/link/route`, проверка gateway/DNS, ping, открытые локальные порты, активные соединения, проверка удалённого TCP-порта.
* Здесь же находится настройка hostname.
* **Защита от потери доступа:** для Netplan изменения применяются через `netplan try` (автоматический откат, если не подтвердить за 120 секунд); для остальных backend — ручное подтверждение с таймаутом и откатом из резервной копии. Любое изменение IP/gateway/интерфейса во время активной SSH-сессии сопровождается явным предупреждением перед применением.

### 🌍 Расположение
Часовой пояс и `chrony` (NTP) объединены в одном разделе, плюс проверка синхронизации времени и быстрый просмотр текущих источников Chrony.

### 🔒 Hardened SSH
* Генерация пары RSA-ключей, конвертация в PPK (для PuTTY), отключение входа по паролю и парольного входа для root.
* **Смена порта SSH** проходит через полный конвейер безопасности: проверка нового порта, проверка, что он не занят другим процессом, резервная копия `sshd_config`, тестовая загрузка новой конфигурации через `sshd -T`, перезапуск SSH только при успешной проверке и автоматическое восстановление резервной копии при любой ошибке. Если UFW активен, скрипт предложит открыть новый порт до применения изменения.
* Скрипт отдельно отслеживает **настроенный** порт SSH и порт, через который работает **текущая сессия**, и предупреждает, если они расходятся (например, сразу после смены порта) — чтобы устаревшая сессия не привела к потере доступа.

### 🧱 UFW (Firewall)
Полностью переработан в консоль управления файрволом: управление службой, просмотр правил, быстрые правила портов/протоколов, правила IP и подсетей (включая source→port), удаление правил по номеру, правила интерфейсов, исходящий трафик, routed/forward-правила, отдельное меню защиты SSH (разрешить текущий порт, ограничить IP/подсетью, `ufw limit`), профили приложений, уровни логирования, политики по умолчанию, расширенный конструктор правил с предпросмотром перед применением и резервное копирование/восстановление правил.
* Включение UFW всегда сначала гарантирует разрешающее правило для **настроенного** порта SSH.
* Удаление или запрет чего-либо, относящегося к порту SSH, порту текущей сессии или IP текущего клиента, требует ввода `YES` для подтверждения.

### 👤 Управление пользователями
Добавление новых sudo-пользователей с автоматическим деплоем SSH-ключей и логированием данных для входа (логика не изменилась).

### 🛡 Fail2Ban
Защита SSH, веб- и почтовых сервисов от брутфорса с автоматической проверкой конфликтов портов. Правило для SSH всегда использует актуальный настроенный порт — включая тот, что был изменён в этом же запуске скрипта.

### 🖥 Динамический MOTD
Генерирует `/etc/update-motd.d/20-server-info` — панель информации о сервере с ASCII-рамкой, которая показывается сразу после SSH-входа (OpenSSH, PuTTY, MobaXterm — отображается одинаково везде):
* Hostname, ОС, ядро, uptime · сеть (интерфейс/IP/gateway по умолчанию) + порт SSH · load, память, диск (`/`) · статус UFW и Fail2Ban · дата/время — **каждая строка включается/выключается отдельно**, с мгновенным предпросмотром.
* Цвета опциональны; рамки — чистый ASCII для максимальной совместимости с терминалами.
* Включение/отключение просто переключает бит исполняемости — настройки никогда не теряются. Удаление затрагивает только файлы, созданные этим модулем; остальные скрипты в `/etc/update-motd.d/` (например, стандартный `10-uname`) автоматически не трогаются, но их можно включать/выключать из того же меню.
* Работает только с локальными данными: без сетевых запросов, без `apt update`, формируется за миллисекунды.

## 🚀 Быстрый старт

> **Внимание:** скрипт должен быть запущен от **root** или через **sudo**.

1.  **Скачать скрипт:**
    ```bash
    wget https://raw.githubusercontent.com/saym101/setup/main/setup.sh
    ```

2.  **Сделать исполняемым:**
    ```bash
    chmod +x setup.sh
    ```

3.  **Запустить:**
    ```bash
    sudo ./setup.sh
    ```

## 🛠 Детали использования

### Логирование
По умолчанию выключено. Приватные ключи (например, дамп PPK при настройке SSH-ключей) выводятся на экран, и при включённом логе полная копия сессии — а значит и приватный ключ — осядет на диске. Включать только при отладке самого скрипта:
```bash
sudo bash setup.sh --log
```
Пишет `setup_ГГГГ-ММ-ДД.log` (права 600) в текущую директорию. После отладки — удалить.

### Создание пользователя
При добавлении нового пользователя скрипт создаёт временный файл в директории `./login` с логином, паролем и путями к SSH-ключам. **Обязательно скачайте эти данные и удалите файл с сервера!**

### ⚠ Оставшиеся секреты — прочитать обязательно
Скрипт генерирует незашифрованные (без пассфразы) приватные SSH-ключи и, для новых пользователей, выводит пароль открытым текстом — и то, и другое остаётся на диске:

* **SSH-ключи (root):** файл `.ppk` выводится на экран для копирования, и скрипт предлагает удалить его после — но **оригинальный** приватный ключ OpenSSH (`~/.ssh/<hostname>-<дата>`) автоматически **не удаляется** и остаётся на сервере.
* **Добавление пользователя:** файл с данными в `./login/<user>_temp_<дата>.txt` содержит пароль открытым текстом и указывает на незашифрованный приватный ключ в `/home/<user>/.ssh/`. Ни то, ни другое автоматически не удаляется.

Как только скопировали ключ/пароль себе — **удалите копию на сервере**: приватный ключ, который даёт доступ к серверу, бесполезно (и опасно) держать незашифрованным на этом же самом сервере — это просто лишний радиус поражения при компрометации.

### Безопасность прежде всего
Скрипт поощряет хорошие практики и активно защищает от потери доступа:
* Принудительный `prohibit-password` для root по SSH.
* Предложение нестандартных портов SSH.
* Настройка правил Fail2Ban с длительным баном (10ч).
* Любое изменение сети, порта SSH или UFW, которое потенциально может оборвать текущую сессию, сопровождается явным предупреждением и запросом подтверждения — скрипт никогда молча не выполняет действие, способное заблокировать SSH-доступ.

## 📋 Требования
* **ОС:** Debian 10/11/12 или Ubuntu 20.04/22.04+ (на базе systemd)
* **Права:** root
* Сетевой модуль сам определяет установленный backend (Netplan / NetworkManager / systemd-networkd / ifupdown) — дополнительные пакеты сверх штатных не требуются.
